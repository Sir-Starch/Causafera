# causal-history-storage - Work Plan

## TL;DR (For humans)
**What you'll get:** A durable causal-history bundle in which the complete canonical event and domain-evidence history lives in append-only cold segments, while runtime state, checkpoints, and snapshots stay bounded. Save/resume, deterministic replay, digest verification, and historical Explanation queries will all use the same committed history contract.

**Why this approach:** The event stream remains immutable authority, a transactional catalog publishes one visible generation across segments/indexes/checkpoints, and the runtime keeps only bounded materialized state plus a cache. This removes the current full-history clone/export/digest path without weakening provenance.

**What it will NOT do:** It will not raise the 256 MiB limit, delete authoritative history, change hydrology semantics, or introduce distributed storage/UI redesign. It will not silently recover corrupt referenced data or treat a bounded Explanation result as authoritative validation.

**Effort:** XL
**Risk:** High - this crosses provenance, persistence, runtime transactions, all current receipt-producing domains, replay, and digest schema compatibility.
**Decisions to sanity-check:** Schema 9 digest semantics, bounded group-commit durability, `rusqlite` bundled catalog, durable bundle-before-first-tick lifecycle, exact legacy-v8 evidence-coverage proof, and the active-segment/catalog commit protocol.

## Scope
### Goal

Make long Causafera simulations viable without making provenance lossy. For a fixed active simulation workload, total causal-history age must not cause ordinary ticks to perform work linear in prior history, must not make runtime hot state or the bounded snapshot grow without limit, and must not materialize the history. Cold storage and derived catalog/index bytes are expected to grow with history; their bounded per-new-record maintenance and measured index/page cost are part of the contract. The full canonical causal and domain-evidence history remains recoverable and independently verifiable.

The implementation must preserve exact event IDs, trace IDs, cause/effect ordering, deterministic proposal/reduce/commit behavior, save/resume state, replay comparison, digest verification, and bounded but historically correct Explanation semantics. The only executable plan is `Causafera/plans/causal-history-storage.md`; tool metadata outside `plans/` is not an architectural source or an execution input. The default durability policy is bounded group commit: logical ticks are atomic in the running process, while the durable generation is forced at most 32 ticks or 250 ms behind and on Save/checkpoint/flush/shutdown. An explicit `EveryTick` mode provides power-loss durability for every completed tick at the measured sync cost. A crash may lose only the unacknowledged logical group; it may never produce a mixed or corrupt world.

### Current state

The authoritative trace store is hot, borrowed `iter()` is a whole-store API with many consumers, snapshot import validates the full graph before state installation, and current transaction rollback depends on a complete `RuntimeState` clone. The runtime has both bounded and unbounded history-shaped fields; moving only the `0x000A` payload would leave clone cost, thermal digest growth, and typed Explanation loss unresolved. Hydrology-disabled ticks also bypass the current hydrology-specific transaction path and must join the new history transaction contract.

### Proposed architecture

#### Logical layers and ownership

1. `causafera-core` owns storage-independent owned record types, canonical causal ordering rules, the `HistoryReader`/transaction-local reader traits, bounded hot cache semantics, and causal batch validation. It must not depend on `causafera-persistence`.
2. `causafera-persistence` owns canonical bytes, segment/frame codecs, `HistoryStore`, the `HistoryCatalog` trait and bundled SQLite implementation, filesystem durability, checkpoints, indexes, recovery, and typed storage errors. It may depend on core, as it already does; no dependency cycle is permitted.
3. `causafera-runtime` owns deterministic domain producers/reducers, the staged runtime state, domain-evidence encoders/decoders, digest field inventory, checkpoint payload assembly, and the bridge from `HistoryTxn` to the scheduler transaction.
4. `causafera-explanation` and observer-facing runtime methods use a pinned, budgeted `HistoryReader`; they never mutate storage and never make Explanation authoritative.

#### Bundle layout and visibility

Every production runtime has a durable bundle before its first tick:

```text
<bundle>/
  catalog.sqlite
  segments/active-<sequence>.cfs
  segments/<content-address>.cfs
  checkpoints/<content-address>.ckp
  snapshots/<generation>.snap
  staging/
  migration/<source-digest>.proof
```

`catalog.sqlite` is the visibility authority for the durable generation. The runtime also has a bounded logical-generation overlay containing at most 32 ticks or 250 ms of frames, whichever is smaller under the configured group policy. A catalog generation is durable-visible only when its SQLite transaction and all referenced frame ranges, sealed segment identities, checkpoints, and snapshot/checkpoint anchors validate. Unreferenced files, uncommitted overlay frames, and active-segment tails are never visible durable history and may only be reported or cleaned by a later explicit maintenance operation outside this plan. `HistoryAnchor` records both `logical_generation` and `durable_generation`; a portable snapshot is resumable only after the requested generation has been forced durable.

#### Canonical record and segment contract

The implementation must add a versioned history format with fixed-width fields encoded by the existing persistence codec conventions and checked arithmetic before allocation:

- `HistoryNamespace`: 32-byte BLAKE3 identity derived from world seed, runtime recipe fingerprint, and the history-format genesis domain.
- `HistoryFrameHeader`: magic, format major/minor, namespace, catalog generation, first/last record sequence, first/last event/trace IDs, prior logical history digest, payload length, and frame digest.
- Frame body: length-delimited records in canonical order. Causal records reuse the current `write_trace_event` field ordering; domain evidence records carry `schema_id`, schema major/minor, criticality (`ReplayRequired` or `ExplanationOnly`), tick/time, sorted/deduplicated causal anchors, canonical key, payload length, and canonical payload bytes. Unknown evidence schemas remain verifiable raw bytes for archival/Explanation inspection, but an unknown `ReplayRequired` schema makes resume/replay fail closed until a decoder/upcaster is available.
- Frame digest: `BLAKE3(history-frame-domain || complete-header-without-digest || payload)`. Sealed segment identity: `BLAKE3(history-segment-domain || immutable-header || complete-frame-range)`. Logical history/evidence digest is a record fold independent of segment boundaries; storage root folds sealed segment identities and active committed ranges separately.
- Canonical ordering is `(commit_sequence, causal-event-before-evidence, event_id/record_key, schema_id, canonical key, payload digest)`; no hash-map iteration, wall clock, locale, or filesystem order participates.
- Limits are checked before allocation: `MAX_HISTORY_RECORDS_PER_FRAME=524_288` (raised from 65_536 on 2026-10-10, see Decision log), `MAX_CAUSES_PER_EVENT=4_096`, `MAX_EFFECTS_PER_EVENT=4_096`, `MAX_FRAME_DECODED_BYTES=128 MiB` (raised from 16 MiB on 2026-10-10), `MAX_CHECKPOINT_DECODED_BYTES=128 MiB`, `MAX_QUERY_PAGE_RECORDS=256`, and `MAX_QUERY_PAGE_BYTES=4 MiB`. Duplicate IDs, unknown parents, invalid offsets, unsupported versions, trailing bytes, overflow, and mismatched counts are hard errors.

The active segment is append-only. Each committed tick writes one complete length-delimited frame; a frame is never split. A frame larger than the 4 MiB target is stored as its own frame/segment unit. A sealed segment may contain complete frames from many ticks, but sealing cuts only between complete frames. Once sealed, a segment is immutable and content-addressed. Catalog rows publish exact `(file, start_offset, end_offset, frame_digest)` ranges, so a crash tail after the last committed range is ignored without truncating referenced bytes.

#### Catalog, indexes, and transaction protocol

The first local backend is `rusqlite` with the bundled SQLite engine, behind `HistoryCatalog`. On open it sets WAL mode, `synchronous=FULL`, foreign keys, a single-writer lock, and schema version checks. The catalog contains `generations`, `segments`, `frames`, `events`, `cause_edges`, `effect_edges`, `evidence`, `checkpoints`, `inputs`, and `snapshots` tables. Indexes include trace/event ID, time, parent/child, domain schema/key, and `latest matching event before (target, property, trace)`; all are derived from canonical frames and rebuildable.

For one successful logical tick:

1. Begin a runtime `HistoryTxn` at the current logical generation/head. Allocate deterministic IDs and validate the proposal/DAG batch against durable and transaction-local records plus the bounded in-memory overlay.
2. Stage bounded runtime deltas, causal events, domain evidence, and recorded external inputs. The transaction-local reader sees prior staged records without publishing them.
3. Canonically encode one complete frame and append it to the active segment; write/flush is allowed, but no per-tick `sync_all` or durable catalog publication is required in the default `GroupCommit` mode. Publish the logical state and overlay atomically in the running process.
4. If the group limit has not been reached, continue. The overlay is bounded by `max_ticks=32` and `max_wall_time=250 ms`, whichever fires first; `Save`, checkpoint creation, explicit `flush_durable`, and clean shutdown force it immediately. `EveryTick` mode skips the overlay and forces this protocol for every tick.
5. A logical-tick failure restores scheduler/system time, bounded state pre-image, pending IDs, hot cache, staged evidence, and overlay; no logical partial tick is visible. A logical tick is not advertised as power-loss durable until its group is published.

For one forced durable group:

1. Complete and flush the active-segment byte range. Call `sync_all` on the segment file and, for a newly created file/directory entry, `sync_all` on its parent directory.
2. Begin an SQLite `IMMEDIATE` transaction with `synchronous=FULL`, recheck namespace, predecessor durable generation, logical frame digests/ranges, head IDs, replay-critical schema availability, and checkpoint references; insert all group frame/index/evidence rows and one durable generation; commit.
3. Sync the catalog/WAL durability boundary and parent directory as required by the backend, then atomically mark `durable_generation = logical_generation` and clear the in-memory overlay. The group commit count and sync latency are measured separately from logical tick cost.

The default contract is therefore bounded group durability, not silent per-tick power-loss durability. A process/power failure may discard only logical ticks after the last durable generation, up to 32 ticks or 250 ms; restart loads exactly the last complete durable generation or a later complete one, never a mixture. `EveryTick` is the explicit high-durability mode and must be benchmarked rather than assumed free.

A checkpoint is immutable state at the latest durable frontier at or before 64 MiB of canonical committed frame bytes or 4096 durably published ticks, whichever comes first, and at explicit Save. Each durable generation points to the latest prior checkpoint; it does not create a checkpoint on every logical tick. A checkpoint contains bounded `RuntimeSnapshotData`, recipe/input fingerprints, event/trace frontier, logical history/evidence digest, storage root, physical v9 digest, and evidence-coverage manifest digest. The SnapshotEnvelope remains a bounded transport copy of current state plus a small `HistoryAnchor` that names the bundle namespace, logical/durable generations, checkpoint digest, frontier, roots, digest schemas, and durability mode; it is not the checkpoint and never embeds the full history.

#### Digest schema 9

The current repository baseline is schema 8. This plan deliberately moves `CURRENT_DIGEST_SCHEMA_VERSION` to 9 and updates the physical, history, and experiment digest call sites together because the current shared marker makes a partial bump invalid.

- `physical_state_digest_v9` covers only current bounded physical/materialized fields that influence the next physical state or identify the current physical state: current material surfaces and pending changes, current pattern state, mana arrays, current thermal parameters/energies/boundaries, resolution, active chunks, actors/objects, population aggregates, and current aggregate pools. It excludes the complete causal store, thermal receipt maps, conservation receipt maps, retention-policy windows, and every bounded historical transition collection whose only consumers are Explanation/observer projections. A field may remain in the physical digest only when its call-site/data-flow inventory proves that it changes future physical evolution or is required to identify current physical state; such fields receive a dedicated test.
- `history_digest_v9` folds the canonical causal-event, domain-evidence, and recorded-input stream using a segment-boundary-independent chain. It covers the historical receipts removed from the physical digest and all required transition evidence exactly once. Its persisted prefix/frontier makes ordinary ticks incremental; the cold reader provides the full-rescan oracle.
- `experiment_digest_v9` is a canonical fold of world/recipe identity, `physical_state_digest_v9`, and `history_digest_v9`. `storage_root` is a separate integrity identity and must not be confused with a physical or experiment digest.
- A v8 legacy snapshot retains its v8 physical/history/experiment values in a migration proof. The proof records the v8 source envelope digest, event/evidence counts, v9 outputs, storage root, migration algorithm version, source-to-destination mapping, and an evidence-coverage manifest. There is no claim that v8 and v9 byte digests are equal.

If another accepted plan increments the digest schema before execution begins, the worker must rebase every schema-9 reference to the next unused schema and record the same field-inventory decision in the canonical plan before editing code.

#### Reader and Explanation contract

`HistoryReader` exposes owned/indexed operations such as `event(trace_id)`, `parents(trace_id)`, `children(trace_id,page)`, `records(range,page)`, `latest_matching_event_before(target,property,trace)`, `evidence(schema,key/page)`, `walk_ancestors(trace,max_depth,max_nodes)`, and `checkpoint_at(time)`. Each query pins one logical generation and its durable base/overlay view, then releases it after the bounded page/result; no query silently crosses generations. Runtime import/reference validation uses unbounded correctness APIs with hard errors, never Explanation's page budget.

User-facing Explanation queries retain the existing 64-trace evidence cap and add explicit `Complete`, `Partial`, `Unknown`, `Missing`, and `IntegrityError` availability. A page or chain budget exhaustion is `Partial`, an unavailable/corrupt/foreign store is `Unknown` or a hard open error as appropriate, and no claim is upgraded because a hot cache happened to contain recent data. Hydrology, thermal, material, bootstrap, and future registered domain readers all use the same boundary.

The evidence registry is part of the replay contract. Every schema declares `ReplayRequired` or `ExplanationOnly`, a supported major/minor decoder, and ordered upcasters for additive historical versions. Causal events, recorded external inputs, and any evidence that influences state evolution or replay validation are `ReplayRequired`. A missing/unsupported `ReplayRequired` decoder is a typed `UnsupportedReplaySchema` hard failure for resume/replay; raw bytes do not satisfy full replay. `ExplanationOnly` data may remain raw-verifiable and appear as `Unknown` when no decoder exists. Existing decoders/upcasters for every accepted bundle remain available, or a migration rewrites the record with a proof before the old decoder is retired.

Every migration writes an evidence-coverage manifest with one entry per schema: role, source availability, first and last copied record/time/trace frontier, complete ranges, missing ranges, copied count, source field, and manifest digest. A legacy snapshot with a complete causal graph but evicted typed receipts is therefore represented honestly: generic causal queries before the coverage frontier remain available, typed Explanation before an unproven frontier is `Unknown` when absence is unknowable, and a request that crosses a known partial range is `Partial`. No migration may claim complete typed evidence merely because the causal graph is complete.

#### Recovery state machine

On open, verify bundle identity, catalog schema, SQLite transaction recovery, logical/durable generation relationship, all reachable segment/frame ranges, index row hashes/foreign keys, checkpoint digest/frontier, evidence-coverage manifest, and the latest snapshot anchor. A missing derived index triggers deterministic rebuild from reachable canonical frames; a missing/corrupt referenced frame, checkpoint, catalog generation, critical replay schema, coverage manifest, or anchor fails closed. An orphan object, an uncommitted overlay frame, or a post-commit-unreferenced tail is ignored/reported, never promoted. In group mode, a crash before frame flush leaves the prior durable generation; after frame flush but before group catalog commit leaves the prior durable generation plus an orphan/tail; during SQLite group commit leaves either the prior or complete next durable generation; after durable commit but before logical overlay publication, restart loads the committed generation and checkpoint. In `EveryTick` mode the same state machine applies per tick. No mixed state is accepted, and a restart reports the exact number/range of logical ticks lost after the durable frontier.

### Primitive vs emergent review

The primitive contract is the immutable canonical record stream, deterministic ordering/IDs, digest/root composition, transactional generation visibility, checkpoint frontier, schema registry, and fail-closed recovery. The hot cache, SQLite indexes, checkpoints, Explanation projections, and benchmark reports are derived/materialized conveniences. Rebuilding or evicting any derived object must not alter canonical bytes, logical digests, replay, or authoritative validation. Domain evidence is a primitive because generic causal fingerprints cannot reconstruct typed hydrology/thermal/material explanations.

### Non-goals

- Do not change hydrology equations, conservation, scheduling phases, ontology labels, event identity, RNG streams, or proposal/reduce/commit semantics.
- Do not raise `MAX_TOTAL_SIZE`, enlarge `retained_batches`, or prune/delete authoritative history.
- Do not add distributed multi-writer replication, cloud object storage, online garbage collection, compression/encryption policy, arbitrary graph-query language, unbounded observer payloads, or UI redesign.
- Do not silently import unsupported legacy section combinations, rewrite historical records in place, or treat missing/corrupt history as an empty graph.

The worker executes one green checkpoint commit per independently verified wave. Checkpoint commits are mandatory during execution, not deferred until the whole plan is done. ## Success criteria

### Verification

The feature is complete only when all of the following are proven by agent-executed artifacts:

- Full causal events and the first-delivery domain evidence are present exactly once in canonical frames, with IDs, cause/effect order, roots, digest folds, and schema versions verified after close/reopen, checkpoint, migration, and resume.
- Ordinary logical ticks use only current-tick writes, indexed reads, bounded group-overlay reads, and configured bounded state/cache. No hot-path whole-history iterator, catalog scan, receipt-map scan, or full snapshot export exists; the full-rescan path remains an explicit cold correctness oracle. Cold catalog/index bytes grow with history and indexed operations may have measured logarithmic/page-cache cost; the contract forbids work linear in prior history or full-history materialization.
- A nine-chunk hydrology run reaches at least 1,000 ticks without 256 MiB export refusal, and the benchmark report shows the specified p95 ratio and no history-age trend in storage work.
- Snapshot envelopes stay bounded and history-size-independent within the 64 KiB differential criterion, remain below the existing 256 MiB hard cap, contain `HistoryAnchor` rather than `SECTION_CAUSAL_TRACES`, and verify their checkpoint/generation/root before import.
- Save/resume and checkpoint replay produce byte-identical v9 canonical history/evidence records, event IDs, state outputs, physical/history/experiment digests, and roots at every forced durable frontier; group mode reports only its bounded unacknowledged logical loss after a crash and `EveryTick` reports zero durability lag.
- A full replay from genesis/recorded inputs and replay from every checkpoint agree with uninterrupted execution; nondeterministic inputs are persisted and included in the history contract; every `ReplayRequired` schema has a supported decoder/upcaster, while unsupported required schemas fail closed before replay.
- Corrupt/missing/foreign referenced objects fail closed; missing derived indexes rebuild deterministically; group-mode crash injection exposes only the previous or complete next durable generation and reports the bounded lost logical range; `EveryTick` crash injection has zero lost committed ticks; orphan/tail artifacts never become reachable history.
- Historical Explanation can page to a 10,000-node/distant chain after hot eviction with explicit availability semantics and the specified latency budget; validation never uses a truncated query.
- The accepted legacy schema-8 matrix migrates idempotently with a proof of old and new digests/counts/roots plus per-schema evidence coverage/frontiers; missing legacy typed receipts yield `Unknown`/`Partial` before their proven frontier; unsupported combinations and unsupported required schemas remain deterministically rejected.

### Determinism impact

No existing proposal/reduce/commit order, explicit RNG stream, event ID allocation, phase, time, locale, or ontology semantics may change. Segment boundaries, SQLite row order, file paths, compression choices, group size, durability mode, and index rebuild order are excluded from logical digest identity. External forcing/experiment inputs are recorded as canonical `ReplayRequired` input records. Replay compares canonical event/evidence bytes and v9 logical digests, not storage offsets; a group crash may discard only records not yet in a durable frontier.

### Memory impact

The complete causal graph and unbounded typed receipts leave `RuntimeState`; only a configured byte-bounded hot cache, current domain state, at most 32 ticks/250 ms of group-overlay records, current-tick staged records, and bounded pre-image/delta state remain. Cold disk/catalog/index usage is expected to grow with history; snapshot and hot-memory acceptance is independent of history age. Decode and query limits are enforced before allocation.

### Observer impact

The observer wire/UI is not redesigned. Runtime observer methods continue to return bounded projections, but their source is a generation-pinned reader rather than an in-memory complete graph. Page/result budgets, explicit evidence availability, and no unbounded payloads remain mandatory.

### Explanation impact

Explanation remains downstream and non-authoritative. It can recover typed evidence from the distant past through the same history store, preserves the existing 64-trace cap and confidence rules, and reports `Partial`/`Unknown`/integrity boundaries instead of narrative completion. No claim may be sourced from a cache-only record that is absent from the canonical reader.

### Persistence impact

The portable snapshot envelope becomes bounded and references a verified durable history bundle via `HistoryAnchor`; the complete event/evidence source of truth is append-only segment data plus a transactional catalog and immutable checkpoints. The format has explicit major/minor/schema versioning, per-object and logical roots, group/EveryTick sync boundaries, logical versus durable generation visibility, bounded crash-loss semantics, recovery, migration proof, evidence coverage, and derived-index rebuild rules. The old full trace section remains a read-only migration input only.

### Cross-domain effects

Hydrology, thermal, material-surface, bootstrap, forcing, and future domain registries share the same generic evidence record contract. Each current domain retains semantic ownership of its payload codec and reducer; persistence owns only bytes, indexes, roots, transactions, and recovery. No domain receives a special retention loophole or changes its physical equations.

### Risks

- SQLite bundled dependency and filesystem sync behavior differ across platforms; lock the compatible version, test Linux/reference CI, and fail clearly where a required durability primitive is unavailable.
- The schema-9 digest migration is a contract change; the source proof and exact field inventory prevent accidental v8/v9 equivalence claims.
- A hot cache can hide missing cold reads during tests; instrumentation and after-eviction tests must force cold paths.
- Group commit can hide durability loss if tests observe only the live process; crash/reopen tests must assert the durable frontier and lost logical range in both modes.
- Replay can silently degrade to archival inspection if schema criticality is not enforced; the registry and `UnsupportedReplaySchema` tests are release gates.
- Legacy v8 typed evidence may have been evicted before export; coverage manifests must distinguish absent source data from a complete empty range.
- Large indexes and long ancestor chains can make Explanation slow; bounded pages, latest-before indexes, and measured latency are part of acceptance.
- Existing callers of `iter()` are numerous and may accidentally retain whole-history assumptions; the code-graph inventory and static hot-path scan are release gates.
- Current legacy fixtures may be generated rather than durable; Todo 1 must commit source bytes before any new writer is used.

- 2026-10-10: A checkpoint's payload is the canonical bounded snapshot envelope, and recovery is checkpoint plus strict replay. `Runtime::open_bundle` restores the latest checkpoint and, if the bundle's durable history runs past it, re-executes those ticks through the ordinary tick path with the history reader pinned at the checkpoint; each re-executed tick's frame must equal the stored frame (generation and every record, evidence included) and is not appended, and any difference fails the open with `ReplayDiverged`. Without replay a crash could not be resumed at all: group publication makes durable generations that no checkpoint covers, and a rewound state could not be appended over them without truncating referenced bytes. Replay costs what the original ticks cost and is bounded by the checkpoint cadence; it relies on one frame per tick, which the open checks (frames after the checkpoint must equal generations after it) and which `TODO-PERSIST-005` would have to revisit.
- 2026-10-10: Automatic checkpoints follow `CheckpointCadence` (default 4,096 durably published ticks or 64 MiB of canonical frame bytes, the plan's thresholds; settable per session, not persisted). One is taken at the next quiescent durable frontier, after the tick that crossed the threshold is published. A failed automatic checkpoint is recorded (`Runtime::last_checkpoint_error`) and never fails the tick, because the tick is already durable history and a missed checkpoint only lengthens the next replay.
- 2026-10-10: Save publishes a checkpoint and a portable snapshot with identical bytes at the forced durable frontier; saving again with no tick between publishes nothing. The checkpoint pointer inside an anchor is navigation, not identity: a snapshot that is the payload of a checkpoint cannot name that checkpoint, so it carries the one before it, while the reader at that generation already points at the new one. `anchors_agree` therefore ignores that field, and `open_bundle` instead checks it against the catalog (it must be the checkpoint before the one being restored, or zero), cross-checks the checkpoint header against the snapshot it carries, and requires a registered snapshot to equal its checkpoint.
- 2026-10-10: What a crash lost is counted by `HistoryStore::open`, not guessed. Group mode appends each tick's frame to the active segment as it commits and publishes the group later, so frames flushed by a dead writer sit past the catalog's durable end. Open walks them, counting a frame only if it continues the committed generation, record sequence and digest chain, so a leftover of an earlier, longer tail that a later writer partly overwrote is not mistaken for the current loss. They are reported (`lost_ticks`, `lost_generations`, `unaccounted_bytes`), never promoted, never truncated; the resumed run simulates the same ticks again identically.
- 2026-10-10: Clean shutdown forces the group. `Runtime::shutdown` does so and reports failure; dropping a bundle session does so best-effort; `Runtime::simulate_crash` skips it for crash drills. `into_history_resume` and `flush_durable` already forced it. `Runtime::assemble` builds the scheduler over an already built state, so resuming no longer constructs and discards a second world with its own temporary store.
